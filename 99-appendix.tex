\section{Process Documentation}
\label{sec:Process Documentation}
%----------------------------------

This appendix provides evidence of the process conducted to produce this assignment: how the
Part 1 position paper was selected and evidenced, and how the Part 2 re-analysis of Task 1 was
carried out, including the code run, its raw console output, and a reflection on issues found
along the way.

\subsection{Part 1: sourcing and verifying the position paper and case study}

The five candidate position papers were checked against their publisher pages and, where
available, secondary reporting (e.g.\ The Conversation, university media coverage) to confirm
scope and findings before one was selected for review. \emph{Relational Futures} was chosen
because it is a substantive, evidenced report (36-respondent survey plus 22 yarning-circle
participants) with a clear purpose and audience, rather than a narrower methods paper. The case
study (predictive risk modelling in Australian child protection) was verified against a
peer-reviewed scoping review~\cite{krakouer2021analysing} rather than a secondary summary, and
was deliberately chosen to be outside the AI systems (companions, chatbots, generative tools)
that \emph{Relational Futures} itself discusses, per the assignment's requirement that the case
study not duplicate the paper's own examples.

\subsection{Part 2: locating and verifying the exact Task 1 pipeline}

Task 1: Part 1 was first written up without its analysis notebook being submitted alongside the
report (only the LaTeX write-up and result figures were originally available for this
deliberation). Dataset A's pipeline was initially rebuilt from scratch, from the two raw UCI
datasets, by following the preprocessing description in Task 1's own process documentation
(cleaning rules, product-week panel construction, feature list, split date). That first
reconstruction reproduced Task 1's reported row counts exactly, but used approximate model
hyperparameters and a slightly different feature set, since the original code was not available.

The author subsequently located and shared the original analysis notebook
(\texttt{Part1\_3\_Analysis.ipynb}) from the project's GitHub repository. Dataset A's pipeline,
model hyperparameters (\texttt{RandomForestRegressor(min\_samples\_leaf=3)},
\texttt{HistGradientBoostingRegressor(max\_iter=400, learning\_rate=0.06, min\_samples\_leaf=20)})
and full 12-feature set (including an \texttt{is\_q4} calendar flag absent from the first
reconstruction) were then corrected to match the real notebook exactly, and re-run
(Listings~\ref{lst:pipeline_a}--\ref{lst:train_a}). This exact pipeline reproduces Task 1's
reported Dataset A table digit-for-digit: MAE/RMSE/WAPE of 129.095/1103.695/0.690 (naive),
113.579/1094.832/0.607 (Random Forest) and 111.235/1095.151/0.595 (Gradient Boosting). All
Dataset A results in Sections~1--4 of the main text (cross-validation, learning curve, and bias
analysis) use this exact, verified pipeline. The original notebook's Dataset B cell was not
recovered before this deliberation was finalised; Dataset B's cross-validation and bias results
therefore use the same-spirit reconstruction described in Section~2.2 of the assignment brief
(stratified split, comparable preprocessing), which independently reproduced Task 1's reported
Dataset B metrics to within a few hundredths (e.g.\ PR-AUC 0.725 vs.\ Task 1's reported 0.721 for
Random Forest) --- close enough to support the qualitative conclusions drawn, but not a verified
byte-for-byte match the way Dataset A is.

Fairlearn's package could not be installed in the sandboxed, offline analysis environment used to
produce this deliberation (no outbound package index access). Rather than substitute an unrelated
tool, its \texttt{MetricFrame} methodology --- computing a metric separately for each group defined
by a sensitive/grouping feature, and comparing the spread --- was implemented directly with
\texttt{pandas.groupby} and scikit-learn metric functions, as shown in the listings above.

\subsection{Reflection}

The main process risk in Part 2 was that the original Task 1 code was not available at the start
of this deliberation, so an initial reconstruction could have quietly drifted from what was
actually run without the author noticing. This was mitigated in two stages: first, by validating
every intermediate quantity (rows retained, panel shape, post-lag row count, held-out metrics)
against Task 1's own reported numbers before treating the reconstruction as a basis for new
analysis; second, once the author located and shared the real notebook, by replacing the
approximate Dataset A pipeline with the exact one and re-running every downstream analysis
(cross-validation, learning curve, bias) against it, rather than leaving the approximate numbers
in place. Dataset B's code was not recovered in time for this deliberation, so its results are
disclosed as an independent reconstruction rather than a verified exact match. One new issue was
found during verification that Task 1 itself did not flag: the \texttt{price\_rel} feature is
computed from each product's median price across the \emph{entire} panel, including weeks after
the train/test cut-off, a mild look-ahead bias. This is disclosed in Section~1.1 of the main text
rather than corrected retroactively, in keeping with Task 1's own principle of reporting the
honest, weaker result. The bias analysis substituted a manually implemented equivalent for
Fairlearn because the package could not be installed offline; this substitution is disclosed in
Section~3 of the main text rather than presented as if Fairlearn itself had been used.
